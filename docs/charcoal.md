# Native charcoal presentation

The Android window and software framebuffer default to `#212121`, independently
of the system night setting. Shared roles and launch/splash resources come from
`isomorphisms/android-NDK` source
`3e682fb1175beef5625dbd2418730220e49fc9bd`, checked out at `_charcoal`.
The fullscreen policy, package, version and registered test signer are retained.

The scene selects light text, walls and handles before the Rough drawing stream
is rasterized. The trajectory remains blue; the endpoint/start markers retain
distinct semantic roles. Paired-edge hues retain their mathematical identities.
Text uses opaque primary/secondary ink, so small labels no longer depend on
translucent dark ink becoming visible over a paper background. The geometry,
collision kernel, animation clock, hit targets and memory limits are unchanged.

The command-line paper drawing streams retain their original colors. They are
exportable drawings rather than an Android window. `BILLIARD_CHARCOAL` selects
the native ink on a host so its actual renderer can be qualified separately.
`make charcoal-pixels` compiles the actual scene and Rough sources through the
same pinned ICK compiler, then checks the charcoal background, light control
ink, nonblank geometry and predominantly dark coverage for the legacy rectangle
and all five cover fixtures. Existing paper-raster and exact-mathematics tests
remain in place. Generated PPM frames are retained with producer evidence.

No source is compiled by a stock compiler. New theme resources are passed to the
existing canonical APK packager through `ANDROID_RES_DIR`; no Java, Kotlin,
Gradle or renderer replacement is introduced.

Android API 29/34 execution, live system-bar checks, startup transition frames,
rotation, both system night settings and physical C67 acceptance are outstanding
until their own receipts are recorded. Host pixels and signed APKs do not
establish those results. Physical A1 acceptance is separate from C67 acceptance.
